## The question

Can optimal transport pair individual mouse cells with "corresponding" human cells, and do such pairs make a cross-species predictor better?

- E1: "Does prior alignment (pairings) of cells ... using Perturb-OT improve cell type prediction accuracy of a MLP+kNN approach?" (`josh@main:e1_perturbot_interspecies.ipynb#c1`) [D]
- E3: can the method predict a cell type that was left out of the matching step (`josh@main:e3_oos_predictions_perturbot.ipynb#c1`) [D]?
- E4 and E12: do the pairs respect subtypes, i.e. CD4/CD8/regulatory T cells and classical/intermediate/non-classical monocytes (`josh@main:notebook_descriptions.md`, `josh@main:e12_perturbot_sublabels.ipynb#c1`) [D]?
- E21: do predictors trained on PerturbOT pairs beat random same-type pairs, plain entropic-GW pairs and cross-species scGen (the autoencoder baseline, F05 onward) in R² and MMD on held-out monocytes and CD8 T cells (`josh@main:e21_perturbot_r2_mmd.ipynb#c1`) [D]?

## Setup

**What PerturbOT is.** PerturbOT (also written Perturb-OT) is a package published on Genentech's GitHub (`josh@main:requirements.txt:103-108`; documentation link at `fasrc:/n/holylabs/mooney_lab/Lab/joshprice/speciesOT/Perturb-OT/README.md:74`) by Jayoung Ryu, Romain Lopez and Charlotte Bunne [D]; Bunne is also the first-listed author of the CellOT paper (author list) [P]. The paper, with Aviv Regev, is "Cross-modality Matching and Prediction of Perturbation Responses with Labeled Gromov-Wasserstein Optimal Transport", arXiv 2405.00838 (`fasrc:/n/holylabs/mooney_lab/Lab/joshprice/speciesOT/Perturb-OT/README.md:79-91`) [D]. It was built to match cells measured with two different assays, with the perturbation as the label (`fasrc:/n/holylabs/mooney_lab/Lab/joshprice/speciesOT/Perturb-OT/README.md:1-2`) [D][I]; here the label is a cell type instead. No notebook in this family cites it [C]. `requirements.txt` installs it from GitHub at commit 3f2dd4b (`josh@main:requirements.txt:103-108`) [C], the same commit as Josh's local clone (`fasrc:/n/holylabs/mooney_lab/Lab/joshprice/speciesOT/Perturb-OT/.git/refs/heads/main`) [G]. Every notebook uses one function, `get_coupling_egw_labels_ott` (`fasrc:/n/holylabs/mooney_lab/Lab/joshprice/speciesOT/Perturb-OT/perturbot/perturbot/match/ott_egwl.py:25-122`) [C]. In plain words:

- Optimal transport (OT) finds the cheapest way to move weight from one set of points to another. Its output, the coupling or transport plan, holds one weight for every (mouse cell, human cell) pair.
- Gromov-Wasserstein (GW) OT compares the two sets only through the distances inside each set, so mouse and human features do not need shared axes.
- Entropic regularisation adds smoothing of strength ε, measured relative to the largest distance (`scale_cost="max_cost"`, `ott_egwl.py:77-78`) [C]. Small ε gives a sharper, near one-to-one plan but is numerically harder. It is solved with Sinkhorn iterations (an iterative rescaling algorithm). The default is ε = 5e-3 (`:26`) [C]; Josh calls ε the "Sinkhorn lambda" or "Sinkhorn entropy parameter".
- The label constraint is a block mask: weight may only flow between cells with the same label (`:16-22`, `:85-92`) [C]. One GW problem is solved for all labels at once (at most 2,000 outer and 2,000 Sinkhorn iterations, `:94-99`), then the plan is cut into one block per label (`:119-122`) [C]. The log lines "running EGWL with ott" and "Done running LEGWOT" refer to this.

PerturbOT also has `train_mlp` (learn a predictor from a plan) and `get_coupling_fot` (match genes to genes). `get_coupling_fot` runs only in the tutorial (`josh@main:perturbOT_tutorial.ipynb#c2`) [C]. `train_mlp` runs in the tutorial and in the first real-data notebook up to `josh@519b22e` (`josh@519b22e:perturbot_interspecies1.ipynb#c8`), but its model is never scored on real data [C]. All later notebooks turn the plan into hard pairs: each mouse cell gets the human cell with the largest weight in its row, the argmax partner (`josh@main:e1_perturbot_interspecies.ipynb#c23`) [C].

**Data.**
- Inputs: `data/tabula_muris/sampled_mouse_shared.h5ad` and `data/tabula_sapiens/sampled_human_shared.h5ad` in Josh's FASRC folder, read by `top_n_organisms_from_species` (`josh@main:speciesot_helpers.py:35-45`) [C]. They are subsamples of Tabula Muris (TM, a mouse cell atlas) and Tabula Sapiens (TS, a human cell atlas), kept to cells that have a coarse cross-species label, `shared_cell_type`. They were written by `josh@main:intraspecies_vs_interspecies_dists.ipynb#c14` and `#c21` [C], first committed on 2025-10-03 (`josh@341b553`) [G]. Both files still exist, last modified 2025-10-03, 1.56 GB and 6.10 GB (`fasrc:/n/holylabs/mooney_lab/Lab/joshprice/speciesOT/data/tabula_muris/sampled_mouse_shared.h5ad`, `fasrc:/n/holylabs/mooney_lab/Lab/joshprice/speciesOT/data/tabula_sapiens/sampled_human_shared.h5ad`; directory listing) [R]. How they were sampled and labelled is in [F01](F01-gw-feasibility-and-simulations.md) and [F03](F03-labels-ontology-and-distances.md).
- Features: the 50 PCA dimensions stored in each file (`obsm['X_pca']`). PCA (principal component analysis) compresses a cell to 50 numbers. Each species' PCA was computed on its own genes (18,024 mouse vs 61,759 human features, `josh@main:e3_oos_predictions_perturbot.ipynb#c18`, `josh@25ae5b9:e3_oos_predictions_perturbot.ipynb#c9`) [N], so the two 50-number spaces are unrelated [I].
- E1, E3: the 8 donors (individual mice or people) with the most cells per species; mouse donor i is paired with human donor i, `pairs = [(i, i+8)]` (`josh@main:e1_perturbot_interspecies.ipynb#c4-6`) [C]. E4 instead pairs mouse donor 2 with human donor 1 (`josh@main:e4_monocyte_subtype_alignment.ipynb#c5`) [C]. `sample_equal_cell_types` shuffles a mouse donor's cells and, for each, takes an unused human cell with the same `shared_cell_type`, until it has n cells (`josh@main:speciesot_helpers.py:101-131`) [C]. Both samples then have the same label mix, and row i of each has the same label. The mix follows the mouse donor and is uneven: one 2,000-cell sample of mouse donor 0 had 503 lung macrophages, 289 intermediate and 267 classical monocytes (`josh@25ae5b9:e4_monocyte_subtype_alignment.ipynb#c10`) [N]. An 80/20 train/test split by row follows (`josh@main:speciesot_helpers.py:157-171`) [C]. These line numbers are from `main`; the version that ran E1 (`josh@77b185c:speciesot_helpers.py:92-114`) does the same on this path [C].
- Seeds. Neither sampling function takes a seed (`josh@main:speciesot_helpers.py:105-106`, `:162`) [C]. But Josh's `fit_mlp` calls `set_seed(42)`, which also reseeds Python's `random` and NumPy's global generator, the two generators these functions use (`josh@main:pytorch_helpers.py:15-20`, `:49`) [C]. So a draw made in a fresh kernel is truly unseeded, while a draw made after a `fit_mlp` call in the same session is fixed by seed 42 [I]. The first case covers the two 2,000-cell default-ε E1 runs, which sample at execution count 6 of a fresh kernel (`josh@519b22e:perturbot_interspecies1.ipynb#c5`, `josh@main:e1_perturbot_interspecies.ipynb#c7`) [N]; the second covers donor pairs 1–4 of E1's second sweep (`josh@main:e1_perturbot_interspecies.ipynb#c34`) [C][I].
- E12: one human donor (TSP14, from cell names in `josh@main:e12_perturbot_sublabels.ipynb#c38`) split into two halves with the same multiset of (cell-type ontology ID, tissue ontology ID), i.e. the standard codes for cell type and tissue, 2,000 cells each, seed 0 (`josh@main:speciesot_helpers.py:323-453`; call in `josh@main:e12_perturbot_sublabels.ipynb#c7`) [C]. This is human vs human, not cross-species.
- E21: the full two files, mouse 10x 3' v2 and human 10x 3' v3 cells only, matched one-to-one by (cell-type ontology ID, tissue ontology ID) (`josh@main:e21_perturbot_r2_mmd.ipynb#c4`, `#c6`; `josh@main:speciesot_helpers.py:455-589`) [C]: 4,027 mouse cells × 18,024 genes (`josh@main:e21_perturbot_r2_mmd.ipynb#c7`) [N].

**Models.**
- Coupling: `get_coupling_egw_labels_ott` on per-label PCA matrices (`josh@main:e1_perturbot_interspecies.ipynb#c10`) [C]. ε values used: default 5e-3 and 1e-9 to 0.1 (E1), 1e-8 (E3, last version), 5e-6 (E4), 1e-4 (E12) [C].
- Predictor (E1, E3): Josh's `fit_mlp`, a multilayer perceptron (MLP, a small neural network) 50 → 50 → 50 → 50 with batch normalisation and ReLU (standard layer types), mean squared error loss, the AdamW optimiser (learning rate 1e-3, weight decay 1e-4), 500 epochs, batch 128 (`josh@main:pytorch_helpers.py:13-33`, `:47-85`; call in `josh@main:e1_perturbot_interspecies.ipynb#c14`) [C]. The layers copy PerturbOT's own MLP: two hidden layers of min(input size, 256) = 50, with the same layer names (`fasrc:/n/holylabs/mooney_lab/Lab/joshprice/speciesOT/Perturb-OT/perturbot/perturbot/predict/mlp.py:17-30`, `:226`) [C]; PerturbOT's run reported a 7.9 K-parameter model (`josh@b296e07:perturbot_interspecies1.ipynb#c10`) [N], which fits this shape [I]. The training does not copy PerturbOT. `train_mlp` draws a fresh partner for each mouse cell from that cell's row of the plan every time the cell is loaded, holds out 5% of cells for early stopping, and uses Adam with batch 256 (`fasrc:/n/holylabs/mooney_lab/Lab/joshprice/speciesOT/Perturb-OT/perturbot/perturbot/predict/mlp.py:100-150`, `:154-189`) [C]. `fit_mlp` trains on one fixed argmax partner per cell [C].
- Training pairs. Arm "no pairings": each mouse training cell with the human cell drawn next to it by `sample_equal_cell_types`, i.e. a random human cell of the same `shared_cell_type` (`josh@main:e1_perturbot_interspecies.ipynb#c12`, `#c14`) [C]. Arm "OT pairings": each mouse cell with its argmax partner (`josh@main:e1_perturbot_interspecies.ipynb#c23-25`) [C]. Both arms use the labels.

**Evaluation.**
- E1, E3, "MLP+kNN" accuracy (`josh@main:speciesot_helpers.py:256-283`) [C]. The MLP turns each held-out mouse cell into a predicted human PCA vector. Its single nearest neighbour (1-NN) among human training cells gives a predicted label. The score is the % of cells whose predicted label is right. All of this happens in the human 50-number PCA space, never in genes. From `josh@519b22e` on, the reference set for the neighbour search is all human training cells in the "no pairings" arm (`josh@main:e1_perturbot_interspecies.ipynb#c21`) but only the argmax-chosen human cells, with repeats, in the "OT pairings" arm (`josh@main:e1_perturbot_interspecies.ipynb#c26`) [C]. Test size is 400 cells at n = 2,000 and 200 at n = 1,000 [C].
- E12: for each source monocyte, is the fine label (`cell_type`, the subtype) of its argmax partner the same as its own (`josh@main:speciesot_simulation_helpers.py:868-896`); class level: `:287-300` [C]. E4 only prints the partners' subtypes and computes no score (`josh@main:e4_monocyte_subtype_alignment.ipynb#c26-27`) [C].
- E21 (planned): R² and MMD (maximum mean discrepancy, a distance between two groups of cells) (`josh@main:e21_perturbot_r2_mmd.ipynb#c1`) [D]. The header does not say in which space; the data prepared in `#c4-6` are log-normalised gene counts, which suggests gene space [I]. Never computed.
- One run per setting. The only spread shown is across 5 donor pairs in E1 (`josh@main:e1_perturbot_interspecies.ipynb#c38-41`) [C].

The MLP then only has to send each label to one point, and the neighbour search can only choose among those points: the test becomes "nearest label prototype" classification [I].
- Where the solver converged (1e-4 to 1e-2), OT pairs averaged 82.4% (15 runs) against 81.8% for random same-label pairs (5 runs). Per pair, the mean of the three converged ε minus the no-pairing value ranged from −1.8 to +3.0 points [I, from `#c35-36`]. ## Verdict
- E1's main claim, that ε ≈ 1e-8 helps, is not supported. The gain appears only where the solver failed (NaN cost, identical results across ε, near-zero training loss) [N]. The mechanism (an all-NaN plan whose argmax pairs every cell of a label with one human cell) is my inference, but each step is visible in the saved outputs and the code. Evidence against the claim: strong.
- With converged solvers, label-constrained GW pairs did not beat random same-label pairs on this metric (82.4% vs 81.8% over 5 donor pairs; below on pair 0 at n = 2,000) [I][N]. Evidence: moderate, since there is one sample per pair and reruns of the same code moved results by about 3 points.
- E1 tests argmax pairs taken from a PerturbOT plan, not PerturbOT's own predictor training, which samples partners from the plan [C].
- E1 does not test label-free cross-species alignment: both arms use the cell-type labels to build pairs, and the score is recovery of those same labels [C][I].
- E3 has one valid test, mast cells, 0 of 24 [N]. The general claim ("no cell types this works for") rests on that one run; every later attempt crashed [N][I].
- E4 has no computed result. My count suggests partial CD4/CD8 matching and no Treg matching; too little to conclude [I].
- E12: in the easiest setting (two halves of one donor), PerturbOT matched monocyte subtypes 56.8% of the time against about 42% by chance, far below the hypothesised 90% [N][I]. One run, unconverged solver. The 100% class-level accuracy is built into the method [C].
- Whether PerturbOT pairs help a predictor measured by R² or MMD was never tested (E21) [N]. The record supports "PerturbOT pairing did not help where it was tested", not "PerturbOT cannot work". ## Terms used here
- **PerturbOT / Perturb-OT**: Genentech package; here only its label-constrained entropic GW matcher `get_coupling_egw_labels_ott` is used.
- **EGW**: entropic Gromov-Wasserstein OT. **EGWL / LEGWOT**: PerturbOT's log names for the label-constrained version.
- **ε, "Sinkhorn lambda", "Sinkhorn entropy parameter"**: strength of the entropic smoothing, relative to the largest distance; default 5e-3.
- **`shared_cell_type`**: coarse label shared by mouse and human, e.g. "T cell", "monocyte".
- **`cell_type`**: the atlas's own fine label, used as the subtype, e.g. "CD4-positive, alpha-beta T cell".
- **donor pair (i, i+8)**: mouse donor i with human donor i, both ranked by cell count; index i+8 because the list holds 8 mouse donors, then 8 human donors.
- **"no pairings" / "OT pairings"**: E1's two ways to build MLP training pairs (random same-label partner vs argmax partner).
- **argmax partner**: the human cell with the largest plan weight in a mouse cell's row.
- **OOS (out-of-sample)**: a cell type left out of the GW step and MLP training (E3).
- **sublabel (subtype) match rate**: share of source monocytes whose argmax partner has the same fine label.
- **human1a / human1b**: E12's two halves of one donor.
- **identity genes**: E12's 11 monocyte marker genes.
- **HSPC**: E21's merged label for hematopoietic precursor and stem cells.
- **autosave copy**: a file in `.ipynb_checkpoints/`, which Jupyter writes on its own; it can hold a state of a notebook that was never committed.
- **`speciesOT_env` / `speciesOT_env_broken`**: Josh's current Python environment and the renamed 2025 one.

## What the package needs from this
Nothing in this family is a good numeric reference test for the scGen/CellOT package. There are no result files, runs are single, and the headline number is an artifact. Five small items are still useful:

1. **Guard test: refuse failed couplings.** If the package ever adds an OT pairing step, it must check convergence and a finite cost before pairing, and it should report the number of distinct partners per label. Input that reproduces the failure: the E1 setup with ε = 1e-9 or 1e-8 (`josh@main:e1_perturbot_interspecies.ipynb#c33-34`). Expected: PerturbOT logs "cost is: nan" in 5 of 5 donor pairs [N]. Tolerance: pass/fail. PerturbOT's matcher imported in the rebuilt environment during the E21 run (section 9), and the 2025 environment also still exists (`fasrc:/n/holylabs/mooney_lab/Lab/joshprice/speciesOT/speciesOT_env_broken`); neither has been re-tested since [I].
2. **Property test: the label constraint.** For any label-constrained plan, argmax partners must have the right shared type 100% of the time (`josh@main:e12_perturbot_sublabels.ipynb#c20`) [N]. Tolerance: exact. This checks the implementation of the constraint, not any science.
3. **Deterministic data check (optional).** `split_adata_by_celltype_tissue` on the top human donor (TSP14) with `cell_number=2000`, `min_per_cell_type=5`, seed 0, then removing generic "monocyte" cells, gives 1,989 cells with the 23-type composition in `josh@main:e12_perturbot_sublabels.ipynb#c11` and 38/28/8 monocyte subtypes (`#c21`) [N]. A March 2026 re-run reproduced these outputs exactly (section 8) [N][I]. Tolerance: exact. Useful only if the package ports this splitter; it is not a scGen/CellOT result.
4. **Weak statistical reference for E1, converged ε only.** Inputs: `fasrc:/n/holylabs/mooney_lab/Lab/joshprice/speciesOT/data/tabula_muris/sampled_mouse_shared.h5ad` and `fasrc:/n/holylabs/mooney_lab/Lab/joshprice/speciesOT/data/tabula_sapiens/sampled_human_shared.h5ad`. Config: donors ranked by cell count, pairs (i, i+8) for i = 0–4, n = 1,000, 80/20 split, ε ∈ {1e-4, 1e-3, 1e-2}, `fit_mlp` (500 epochs, batch 128, learning rate 1e-3, seed 42), 1-NN in human PCA space, OT arm searched against its argmax-chosen cells. Expected: OT pairs 76.0–87.5% (mean 82.4%), random same-label pairs 76.0–85.5% (mean 81.8%) (`josh@main:e1_perturbot_interspecies.ipynb#c35-36`) [N]. Tolerance: about ±3.5 points per run (two reruns of identical code differed by 3.0 and 3.5 points, section 3) and 2–4 points across donor pairs [I]. Pairs 1–4 were drawn right after `fit_mlp` had reseeded the global generators, so an exact copy of Josh's call order might redraw the same cells; untested [I]. Only distribution-level agreement can be relied on. Low priority.
5. **E21 as a future design, not a reference.** PerturbOT-pair MLP vs random-pair MLP vs EGW-pair MLP vs scGen, scored by R² and MMD on held-out monocytes and CD8 T cells, with cells matched by cell-type and tissue ontology IDs (`josh@main:e21_perturbot_r2_mmd.ipynb#c1`, `#c6`) [D][C]. It would fit the package's model and evaluation classes (`josh@scgen-model-impl:src/speciesot/speciesot_core.py:35-57`, `:305-334`) [C]. No expected numbers exist. PerturbOT ships its own forks of `ott` and `scvi-tools` and needs an old jax (`fasrc:/n/holylabs/mooney_lab/Lab/joshprice/speciesOT/Perturb-OT/README.md:20-34`; `josh@7e69bb1`) [D].
