# F09 · The experiment infrastructure: the `hub` CLI, specs, the vault and metric sidecars

> This page is about tooling, not an experiment. From late May to August 2026 Conny, working with AI coding agents, built `./hub`: a command-line tool that finds every trained run on disk, reads its config and evaluation files, and writes tables, model cards, Obsidian notes and a leaderboard; it also turns one YAML "spec" into a dataset, two training configs and six Slurm job scripts. Versions 0 to 1.1 were committed within 23 hours (2026-05-28 15:55 → 05-29 14:35); data preparation, metric "sidecar" files, the Obsidian vault and the leaderboard followed by 2026-06-11, and 11 experiment cells (22 model folders) were later created from specs. It worked as a launcher and as the home of the decoded-frame metric, but its saved views went stale (model cards frozen on 2026-05-28, vault notes on 2026-06-09, so the Obsidian leaderboard is empty), several of its labels are guessed from folder names, and its leaderboard ranks runs from nine different datasets on one fraction that reaches 1.032. Status: infrastructure; its data-prep and metric code is worth porting to the package, its discovery guesses and saved views are not.

## The question

There was no scientific question. The problem was bookkeeping:

- By 2026-05-28 there were 175 model folders (folders with a `config.yaml`) in two result trees (`conny@181306e` message) [D], with ten different model-folder names for four model families (HUB `resolve.py:17-36`; CF:117-141) [C][D].
- The only inventory was a hand-written script (section 1 below). Each new experiment shape needed a new generator script, "essentially a fork of an existing one" (WT, section "Declarative experiment-spec system") [D]. Data prep was a notebook whose first chunk took "forever" (HD:342) [D].
- Stated goals, 2026-05-25 to 05-29: a "model-card hub", because "notebooks are scaffolding; trained models are the actual deliverable" (WT, "Separate project: Model-card hub") [D]; a roadmap v0 read-only catalog → v1 spec-driven generator → v2 submission and lifecycle → v3 viewer (WT, "Hub absorption roadmap") [D]; one spec and one command per new experiment (HD:351-362) [D].
- Added on 2026-06-09/11: one fixed number to answer "are we improving?" (CF:811-847; AGENTS.md:31-45) [D].
- Deliberately excluded: the hub never submits jobs; a human copies the printed `sbatch` lines (HH:148-150) [D].

## Setup

### Code, environments, commands

- `./hub` is a bash wrapper. It activates the `CellOT` conda env and runs `python -m speciesOT.hub.cli` (`conny:hub:14-43`) [C]. The package has 14 Python files and 5,254 lines (`wc -l` on HUB) [C]; HH:48 still says "~4,500 LOC across 12 modules" [D].
- Environments: `CellOT` has python 3.9, anndata 0.7.6 and torch 1.11; `analysis` has scanpy 1.12 (ENV:20-23) [D]. `./hub prep` runs its work under `analysis` and calls back into `CellOT` to rewrite the file for anndata 0.7 (HUB `cli.py:428-473`; HUB `prep.py:19-32`) [C].
- Commands (HUB `cli.py:824-1083`) [C]:

| command | what it does | writes to |
|---|---|---|
| `list` | one row per run; `--filter key=value`, `--sort` | screen |
| `show <run_id>` | all recorded fields of one run and each of its evaluations | screen |
| `compare A B` | fields that differ (the "cause") and metric differences per eval folder (the "effect") | screen or file |
| `export csv\|md` | flat inventory, 35 columns | `experiments_inventory.{csv,md}` |
| `card [--all]` | one Markdown card per run, plus `INDEX.md` | `docs/model_cards/` (gitignored) |
| `attach-figures` | links matching figures from `speciesOT/baseline/analysis/*_outputs/` into `<model_dir>/figures/` | symlinks |
| `vault` | one Obsidian note per run, plus an index | `docs/experiments/` (tracked) |
| `scorecard` | runs that have a decoded sidecar, sorted by `frac_gap_closed_decoded` | screen or file |
| `spec dump <run_id>` | rebuilds a spec from a run's config | YAML |
| `generate <spec>` | 2 configs, a `model-scgen` symlink, 6 job scripts; prints the submit chain | `RES/<tag>/`, `sbatch/` |
| `prep <spec>` | builds the training `.h5ad` | `cellot/cellot_gpu/datasets/` |
| `metrics <run_id>` | runs the two transport sidecar scripts on each data-space evaluation | sidecar CSVs |
| `handoff <run_id>` | manifest of dataset, preprocessing and model settings | `handoff/*.json`, `*.md` |
| `lps …` | six subcommands for the LPS studies ([F13](F13-autoresearch-loop.md), [F15](F15-ae-repair-rounds-and-calibration.md)): four `*-generate` ones check inputs (two also run a study script that writes a manifest) and print `sbatch` lines; two `*-summarize` ones run a study script that merges results (HUB `lps.py:29-232`) | screen, study folders |

- The hub never calls `sbatch`. Its only subprocess calls start Python scripts (HUB `cli.py:472, 524`; HUB `lps.py:37, 180, 222`; HUB `prep.py:372`) [C]. But `prep` and `metrics` do heavy work in the calling shell; on the cluster they were wrapped in hand-made job scripts (`fasrc:BK/sbatch/prep/prep_atlas_cd8_uncapped_v08.sbatch`, `fasrc:BK/sbatch/metrics/metrics_and_identity.sbatch`) [C]. The prep job scripts skip `./hub prep` and call `python -m speciesOT.hub.prep` with the `analysis` interpreter's absolute path, because "`conda activate analysis` does not reliably switch PATH in batch here" (`prep_atlas_cd8_uncapped_v08.sbatch:17-23`; `prep_mixhvg_cd8_uncapped_v08.sbatch:19-25`) [C][D].

### The data model: run_id, families, aliases, phases

- A run (a `ModelRecord`, HUB `catalog.py:59-118`) is any folder that contains a `config.yaml`, under two roots: RES (tag `gpu`) and `conny:speciesOT/baseline/results` (tag `baseline`). `_archive/` folders are included (HUB `discover.py:40-59`) [C].
- `run_id` = root tag + path below the root, e.g. `gpu/hvg_pearson_residuals_m1_v08_ood/impact_cellot` (HUB `discover.py:192-198`) [C]. A unique ending also works (HUB `catalog.py:129-154`) [C]. Each `evals_*` folder with a non-empty `evals.csv` is one evaluation record, keyed by the folder name (HUB `discover.py:62-100`; HUB `catalog.py:22-56`) [C].
- The family comes from the folder name through an alias table (HUB `resolve.py:17-69`) [C]:

| family | folder names that map to it |
|---|---|
| `scgen` | `scgen`, `speciesot_scgen` |
| `impact_cellot` | `impact`, `impact_cellot`, `impact_or`, `swapped_cellot`, `speciesot_cellot` |
| `cellot_celltype` (abandoned cell-type framing) | `speciesot_cellot_swapped`, `normal_cellot`; bare `cellot` in the speciesot_v1 or toggle phases |
| `cellot_legacy` | top-level `cross_species_ood*` and `race*` folders |
| `cellot_unresolved`, `unknown` | fallbacks for anything else |

- "Phase" is guessed from the experiment folder's prefix (`hvg_`, `toggle_`, `renorm_`, `atlas_full_`, `speciesot_`, `cross_species_`/`race`; `bcg` anywhere in the name). The code uses it only to resolve a bare `cellot` folder, and it is not stored (HUB `resolve.py:58-94`) [C]. `generated_by` is guessed by a separate prefix rule (HUB `resolve.py:117-126`) [C].
- What is read and what is guessed:

| field | source | how (code) |
|---|---|---|
| holdout, mode, hyperparameters, `ae_emb` path | `config.yaml` | read (HUB `discover.py:206-301`) [C] |
| data source, normalization, HVG method and input layer, `log1p_applied` | data file name | substring rules (HUB `discover.py:103-178`) [C] |
| `hvg_batch_key` | — | always empty (HUB `discover.py:218`) [C] |
| status | `cache/status` | read; `never_started` if missing (HUB `readers.py:29-38`) [C] |
| eval space and setting | eval folder name | parsed (HUB `readers.py:62-80`) [C] |
| R², MMD | `evals.csv` | `r2-*` rows squared, then mean over draws at the largest `ncells` with `nfeatures == "all"` (HUB `readers.py:41-106`) [C] |
| `generated_by` | experiment folder prefix | guessed (HUB `resolve.py:117-126`) [C] |
| split seed, `test_size`, `stratify`, device, git commit, environment | — | not recorded [C] |

### From spec to configs and job scripts (the "three-layer YAML system")

- Upstream CellOT has three layers of YAML: task templates (`configs/tasks/*.yaml`: data and split), model templates (`configs/models/*.yaml`: model, optimizer, training), and the merged config that `train.py` writes into each result folder (HD:259-275) [D]. This project's generators, and later the hub, write the merged config directly from text templates; the two template layers are never read (HD:277-279; HUB `spec.py:388-465`) [D][C]. Thirteen old task templates were archived in `conny@10c4a36` [G].
- So the hub's "scgen" (hidden layers [256, 256], dropout 0.1, 50,000 iterations; HUB `spec.py:142-146, 403-421`) differs from the upstream template ([512, 512], dropout 0, 250,000 iterations; `conny:cellot/cellot_gpu/configs/models/scgen.yaml`) [C]. It is CellOT's deterministic autoencoder (AE) with `beta: 0.0`, not a VAE (HUB `spec.py:404`; `conny:docs/archaeology/models.md`) [C].
- A spec (`ExperimentSpec`, HUB `spec.py:54-167`) has about 40 fields: tag and `derived_from`; source files, `assay_filter`, `cap_cells_per_type`, ortholog source, `source_backed`; HVG method, number of genes, input layer, batch key; condition, source and target; holdout, split strategy, mode, `test_size`, `random_state`, `datasplit_stratify`; scGen and IMPACT hyperparameters; IMPACT training device; eval `n_cells` [C].
- For a tag T, `generate` writes `RES/T/scgen/config.yaml`, `RES/T/impact_cellot/config.yaml` (whose `data.ae_emb.path` is `./results/T/scgen/`), the symlink `RES/T/model-scgen → scgen`, and six job scripts in `sbatch/train/`, `sbatch/eval/` (latent space) and `sbatch/eval_dataspace/` (HUB `spec.py:646-712`) [C]. It prints a submit chain with `--dependency=afterok` (HUB `spec.py:715-734`) [C].
- The evaluation flags follow the rule from CF §5.5: scGen latent-space evals get `--embedding ae`, IMPACT latent-space evals do not, and IMPACT data-space evals always do (HUB `spec.py:555-602`; CF:347-362) [C][D].
- When training starts, CellOT's `train.py` overwrites `config.yaml` with a plain `yaml.dump` (`conny:cellot/cellot_gpu/scripts/train.py:35-37`) [C]. The `# derived_from` header written by the hub (HUB `spec.py:390-391`) is therefore lost.

### Data prep (`./hub prep`)

- A port of notebook 01.5 (HUB `prep.py:1-17`) [C]: load the source atlases and their raw counts; apply the assay filter (one sequencing platform per species, enforced since 2026-06-05; HUB `spec.py:84-96`) [C][D]; map mouse to human genes with BioMart one-to-one orthologs, cached in `scripts/.biomart_ortholog_cache.csv` (HUB `prep.py:388-412`), a file untracked since `conny@bcce463` [C][G]; match cells by (cell type, tissue) with the spec's seed; keep counts in a layer and log-normalize `.X`; select HVGs on the non-held-out cells with each flavor's input layer; keep the held-out cells in the file; write; rewrite for anndata 0.7 (HUB `prep.py:484-633`) [C].
- The two ensemble flavors `mixhvg` and `mixhvg_default` need the separate `mixhvg-py` package (HUB `prep.py:125-200`; HU:261-281) [C][D]. Large atlases use a separate backed reader (HUB `prep_backed.py:1-20`) [C].
- `cap_cells_per_type` is recorded in specs but neither prep path reads it; the cap follows from which source file the spec names (`grep` over HUB `prep.py` and HUB `prep_backed.py`) [C].
- The ortholog cache is not in BK: `fasrc:BK/scripts/` holds only `__pycache__/` (`ls -la` on FASRC) [R]. The last tracked copy, 14,451 one-to-one pairs, survives only in git history (file `scripts/.biomart_ortholog_cache.csv` as of `conny@c342331`; untracked in `conny@bcce463`) [G]. Both surviving prep logs report 14,451 aligned genes (section 4), which fits that table [R][I].

### Metric sidecars and how `readers.py` picks them up

A sidecar is a CSV that a separate script writes next to `evals.csv`, so that CellOT's own `evaluate.py` stays unchanged (AGENTS.md:84-86) [D]. What the numbers mean (floor, ceiling, decoded frame) is in [`metrics.md`](../metrics.md) §3 and [F10](F10-monocytes-floor-ceiling-and-v08.md).

| file | written by | where | read by the hub | fields the hub uses |
|---|---|---|---|---|
| `extended_metrics.csv` | `conny:cellot/cellot_gpu/scripts/extended_metrics.py` | `evals_*/` | yes (HUB `readers.py:109-132`) | `mmd_floor`, `mmd_ceiling`, `frac_gap_closed`, `mean_js` |
| `decoded_frame_metrics.csv` | `conny:cellot/cellot_gpu/scripts/decoded_frame_metrics.py` | `evals_*/` | yes (HUB `readers.py:135-169`) | `frac_gap_closed_decoded`, `frac_r2_closed_decoded`, `mmd_ae_recon_floor`, `mmd_decoded_ceiling` |
| `ae_identity_metrics.csv` (+ per-cell, per-gene, manifest) | `conny:cellot/cellot_gpu/scripts/ae_identity_metrics.py` | `<scgen folder>/ae_identity/` | no | — |
| `eval_clouds.npz` | `conny:cellot/cellot_gpu/scripts/dump_eval_clouds.py` | `evals_*/` | no (a cache the two scripts reuse) | — |

- The hub keeps only the sidecar row with the largest `ncells` (HUB `readers.py:127, 159`) [C].
- `./hub metrics` runs both transport scripts on every eval it labels `data_space`, always with `--where data_space --embedding ae`; the scripts default to `n_cells` 30, 50, 80, 10 draws and `random_state` 0 (HUB `cli.py:493-524`; `conny:cellot/cellot_gpu/scripts/extended_metrics.py:86-93`) [C]. Until 2026-06-11 it ran only `extended_metrics.py`; the decoded script was added to it in `conny@2c68571` [G], so the decoded sidecars dated 06-09 were made by running the script directly [I]. Both scripts find the autoencoder through the `model-scgen` symlink (`conny:cellot/cellot_gpu/scripts/extended_metrics.py:117-119`; `conny:cellot/cellot_gpu/scripts/decoded_frame_metrics.py:118-124`) [C].

## Verdict

- **As a launcher it worked.** Eleven cells were created from specs [R]. The backed prep path built the two uncapped CD8 datasets end to end, with identical cell counts on 06-05 and 07-30 (job logs, reference test 4) [R]. The hub's own eval scripts carry the right `--embedding` flags, so its data-space IMPACT evaluations are in gene space by construction (HUB `spec.py:579-602`) [C].
- **As a metric home it worked.** It made the decoded-frame metric a routine sidecar (21 files) [R], and an independent code path reproduces one of them to within 1e-8 (see the first reference test below) [R].
- **As a catalog it can only be trusted for what it reads directly from files** (configs, `evals.csv`, sidecars). It cannot be trusted for the guessed fields: eval space for older IMPACT runs (29 in the HVG matrix, plus `hvg_pearson_residuals_a_ood_uncapped`), `generated_by`, data provenance beyond the file name [C][R][I]. The saved views (cards, vault notes, inventory exports) are months out of date and point to deleted paths [R][G].
- **As a judge it does not answer "are we improving?" across datasets.** The scorecard ranks 17 runs from 9 datasets on a fraction whose denominator varies 3.5-fold and which can exceed 1 [R]. Only comparisons inside one dataset are interpretable [I]; used that way (07-21, m1 and m2 v08) it gave a clear within-dataset answer [D][R].
- **Evidence strength.** Code behaviour [C] and file counts [R] are solid. The prep, metrics and handoff code was committed days after it was used, inside a commit with an unrelated title [G]. Their dates still hold: a handoff output generated 06-04, prep logs and dataset file times of 06-05, and sidecars dated 06-05 match what HH says [R][G][D].

## Terms used here

- **hub, `./hub`**: the CLI in HUB; AGENTS.md:58 calls it "the system of record".
- **run, run_id**: one folder with a `config.yaml`; id = root tag (`gpu/` or `baseline/`) + path.
- **family / alias**: the canonical model kind (`scgen`, `impact_cellot`, `cellot_celltype`, `cellot_legacy`) / an older folder name that maps to it.
- **phase**: project era guessed from the tag prefix; not stored.
- **eval_id, space, setting**: the `evals_*` folder name and the two words parsed from it (`data_space`/`latent_space`, `ood`/`iid`).
- **headline (hub)**: mean over the 10 draws at the largest `ncells`, all features, with r squared.
- **sidecar**: a metric CSV written beside `evals.csv` by a separate script.
- **spec, cell**: one YAML `ExperimentSpec` / the scGen + IMPACT pair it produces.
- **`model-scgen`**: symlink in each experiment folder that tells every eval script which AE to use.
- **three-layer YAML system**: CellOT's task templates + model templates + merged config.
- **intent fields**: spec fields that cannot be read back from a trained config (assay filter, cap, stratify, device…).
- **`north-star`, `guardrails`**: the repo's headline metric (`frac_gap_closed_decoded`) and its two cross-checks.
- **`frozen benchmark`**: the three v08 OOD cuts on which AGENTS.md wants model versions compared.
- **`fgc_dec`, `fr2_dec`, `fgc_raw`**: scorecard column names for the decoded gap fraction, the decoded R² fraction and the raw gap fraction.
- **vault, MOC, Dataview**: the Obsidian notes folder `docs/`, its index pages, and the plugin that turns note headers into tables.
- **card**: the HPC-only Markdown page per run from `./hub card`.
- **aeflag**: the 10 HVG-matrix re-evaluations that added `--embedding ae` ([F08](F08-hvg-flavor-matrix.md)).
- **v07 / v08 / uncapped**: dataset versions → [F10](F10-monocytes-floor-ceiling-and-v08.md), [F16](F16-deployment-models-and-mixhvg.md).
