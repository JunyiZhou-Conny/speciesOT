# F16 · Deployment models, external-target evaluation, and the mixhvg ablation

> Two linked lines of work. First, Conny trained "deployment" models: scGen-style and IMPACT_CellOT mouse→human models with no cell type held out, meant to be applied to a new dataset (BCG mouse cells) rather than to measure generalization. Around them Conny built the hand-over tooling: a prediction script with gene-axis checks, "baked" sidecar files that make a model self-contained, a scorer against an external human ground truth, one Python environment that reads both `.h5ad` formats, and a runbook for Josh. Second, Conny tested whether an ensemble gene-selection method (mixhvg) beats Pearson-residual genes on the three benchmark holdouts (M1, M2, atlas CD8). The tooling passed its own checks and two model sets were used for BCG predictions (F17), but no deployment model was ever scored on held-out atlas cells with a floor and ceiling, and the last set (`uncapped_v08`, 2026-08-18) was trained (its checkpoints exist) but never evaluated or used. The mixhvg ablation is inconclusive: the top score of 1.032 rests on a weak, gene-set-specific floor, and on M1 mixhvg is worse than Pearson residuals on every IMPACT metric. Status: partly worked.

## The question

- **Deployment.** Train mouse→human models that have seen every cell type, so they can be applied to an external mouse dataset (BCG). "The trained model is intended for downstream prediction on external data (BCG mouse), so we want it to have seen every cell type during training" (nb15#c0) [D]. Then make it possible for Josh, who had never used the repo, to run predictions himself (PLANLOG:6-9) [D], and to score them against real human cells from another study (RB:46-54) [D].
- **mixhvg.** Does an ensemble highly-variable-gene (HVG) selection produce better models than the single Pearson-residuals flavor, with everything else fixed? "the only variable is which 1000 genes get selected" (`conny:specs/mixhvg_m1_v08.yaml:52-54`) [D]. An HVG flavor is the recipe that picks the 1,000 input genes (see [F08](F08-hvg-flavor-matrix.md)).

**Data.** Every dataset here is one-to-one orthologs (14,451 genes), mouse and human cells matched per (cell type, tissue), counts → `normalize_total` to 10,000 over the 14,451 genes → log1p, then the top 1,000 HVGs (nb15#c3, #c11, #c16; PREP) [N][R].

- The assay filter removed most CD8 T cells from `atlas_full_v07`: 62 cells instead of 390; HSPC is the largest class, 1,782 of 8,610 cells (nb15#c7) [N]. Two cell types vanish entirely, regular atrial cardiac myocytes and alveolar type 1 cells (nb15#c7) [N].
- Gene axes differ between datasets [R] (gene lists from RES/atlas_full_*/genes.txt and the `gene` column of RES/*_v08_ood/scgen/ae_identity/ae_identity_pergene.csv): `atlas_full_v07` pearson vs `a_uncapped_v08` pearson share 721 of 1,000 genes (this confirms PNI:23-25); `atlas_full_v07` pearson vs seurat_v3 share 586; mixhvg vs pearson share 724 (M1), 726 (M2), 674 (CD8).
- "v07" has two meanings. `_v07.h5ad` is a file written by anndata 0.7 for the CellOT environment (nb15#c18) [C]. "v07 cut" also means data built before the 2026-06-05 assay filter (`conny:docs/conceptual_framework.md:876-878`) [D]. `atlas_full_v07` carries the file suffix, but its May-10 data already had an assay filter (nb15#c11 asserts it) [N].

**Models.** Both families come from the CellOT code in this repo, trained for 50,000 iterations with no training seed [C] (RES/atlas_full_pearson_residuals/{scgen,impact_cellot}/config.yaml; see [F08](F08-hvg-flavor-matrix.md)):
- "scGen" = CellOT's autoencoder (AE) 1000→256→256→50, dropout 0.1, beta 0 (no KL term). Prediction: encode the mouse cell, add the shift (mean human code − mean mouse code over the training split), decode (PNI:655-663) [C].
- IMPACT_CellOT ("IMPACT") = an input-convex network (4 hidden layers of 64) that maps mouse codes to human codes in the latent space of the sibling scGen AE, then decodes through that AE (PNI:664-676) [C].
- The checkpoint that prediction and evaluation load is `cache/model.pt`. Training overwrites it each time a check on the test split improves: the AE reconstruction loss on one test batch every 1,000 steps, or the IMPACT test MMD every 250 steps (`conny:cellot/cellot_gpu/cellot/train/train.py:152-159, 233-240`) [C]. So it is the best checkpoint by that check, not the step-50,000 model. Example: the deployed pearson scGen `model.pt` is dated 05-10 11:46, about nine minutes into a 40-minute run that lasted 11:38–12:18. The checkpoint time comes from a FASRC listing of `fasrc:BK/cellot/cellot_gpu/results/atlas_full_pearson_residuals/scgen/cache/`; the run time comes from the progress bar and file time of `train_12213987.err` [R]. For the deployment sets the test split is the 20% (`atlas_full`) or 5% (`uncapped_v08`) split. The `uncapped_v08` spec says the 5% split is "for eval_freq only" (`conny:specs/atlas_uncapped_pearson_v08.yaml:53-54`) [D], but it also chooses the checkpoint [C].

**What each deployment set was trained on** (all `random_state` 0; split code `conny:cellot/cellot_gpu/cellot/data/cell.py:330-384`) [C]:

| model set | folders | split | training cells |
|---|---|---|---|
| `atlas_full_v07` | RES/atlas_full_{flavor} | train_test, 20% test | 6,888 of 8,610 (RB:597 says 6,888; 0.8 × 8,610) [D][I] |
| `uncapped_v08_iid` ("iid twins") | RES/hvg_{flavor}_a_uncapped_v08_iid | toggle_ood, mode iid, CD8 held out | 71,290 of 89,760: 70,420 non-CD8 + 870 CD8 (split counts of the identical OOD split in MID) [R][C] |
| `uncapped_v08` | RES/hvg_{flavor}_uncapped_v08 | train_test, 5% test | 85,272 (0.95 × 89,760; section 10) [C][I] |

The `toggle_ood` split first puts 80% of all cells in train and 20% in test, then cuts the held-out type in half: in iid mode one half joins training and the other half is the scored "ood" set (cell.py:348-380) [C]. So the iid twins never see the cells they are scored on.

**Evaluation.** Two code paths. (1) Atlas runs: `evaluate.py` draws n = 30, 50, 80 cells, 10 unseeded draws, and writes unsquared r and biased MMD to evals.csv; `extended_metrics.py` adds a raw-frame floor and ceiling and `decoded_frame_metrics.py` a decoded-frame floor and ceiling (definitions in [metrics.md](../metrics.md) and [F10](F10-monocytes-floor-ceiling-and-v08.md)) [C]. The sidecars recompute the model MMD themselves with seeded draws (`random_state` 0; `conny:cellot/cellot_gpu/scripts/decoded_frame_metrics.py:109, 129-131`) [C], so their model MMD differs slightly from the evals.csv mean (by up to 0.003 in the table in section 7) [R]. R² below is the hub's: r squared, averaged over the 10 draws at n = 80 (`conny:speciesOT/hub/readers.py:41-60, 83-100`) [C]. (2) External data: EET builds the same decoded floor and ceiling from three clouds (prediction, real target, source) with seeded draws (`random_state` 0), n = 30, 50, 80, 10 reps, 50 bandwidths, and 50 "marker" genes derived as the largest |mean(target) − mean(source)| (EET:12-28, 211-239, 421-430) [C].

**mixhvg.** A rank-max ensemble of four HVG scores (scran, seuratv1, mv_PFlogPF, scran_pos): each method ranks every gene and a gene keeps its best rank (`conny:speciesOT/hub/prep.py:87-92, 167-177`; `fasrc:BK/mixhvg-py/README.md`) [C][D]. It is computed per species and the two species are combined by median rank first, number of species second (prep.py:180-217) [C]. That is scanpy's seurat_v3 rule (`conny:docs/hub_usage.md:281`) [D]. scanpy's pearson_residuals sorts the other way: number of species first, then median rank (local scanpy 1.12.1, `scanpy/experimental/pp/_highly_variable_genes.py:242-247`; F08 found the same in the FASRC env) [C]. The port lives in a separate GPL-3 repository; vendoring it would make this repo GPL-3 (`conny@9b30aa5`; [sources.md](../sources.md)) [G][D].

## Verdict

- **Tooling.** The prediction script, gene-axis guard, sidecars, converter and scorer exist and are documented. The scorer reproduces the benchmark sidecar within 1e-8 [R]. The prediction script ran on real BCG input on 08-18 and wrote all eight files for the `uncapped_v08_iid` set (section 2) [R]. Whether those predictions are any good is F17's question. The other "bit-identical" and "verified" claims are [D] only: their inputs and outputs were in `/tmp`.
- **Deployment models.** None was ever scored on held-out atlas cells against a floor and ceiling. Their quality as deployment models is unknown from this record [R][I]; the only external test is the BCG application (F17). The May BCG prediction set mixes two model generations (section 1) [N][R]. The runbook mislabels the default set as pre-assay-filter (see Problems).
- **mixhvg.** Nothing supports "mixhvg is better". On M1 it is worse for IMPACT on every performance measure [R]. It wins on model/floor and fgc_dec for IMPACT on M2 and CD8 and for scGen on all three cuts [R]. But each flavor is scored on its own genes, with its own AE, floor, ceiling and do-nothing baseline, and each cell of the table is one unseeded run [R][I]. Inconclusive.
- **A lesson worth keeping.** The decoded-frame fraction and model/floor both rate raw untransported cells as nearly as good as IMPACT on M1 (0.874 vs 0.897) [R]. These metrics need a frame check and the R² guard beside them.

## Problems in how it was done

- **Runbook mislabels the default model set.** RB:76 and RB:545-554 say `atlas_full_v07` was trained "before the assay filter" on data mixing Smart-seq2 with 10x. The deployed checkpoints are from the 05-10 retrain (`model.pt` dates, FASRC listing) [R], most likely on the 8,610-cell, 10x-only file (section 1) [I]. The runbook itself quotes 8,610 cells and 6,888 training cells (RB:159, 597) [D]. The description fits the overwritten May-8 models. PNI:17 also calls the set "the May-8 deployment models" [C]. RB:123-125 adds that they "were trained on *all* atlas cells"; in fact they were trained on 6,888 of 8,610 (80%) [D][C]. Readers would wrongly discount these models, or think they had seen every atlas cell.
- **Wrong training-set claims for the iid twins**: "all 89,760" vs 71,290, and "seen in training" vs never seen (section 8) [D][C][R]. The runbook's "hold out no cell type" (RB:137-139) [D] repeats the first error. A reader would treat the iid evaluation as a training-set check.
- **The May BCG prediction set is mixed.** IMPACT/pearson comes from the May-8 model; the other three come from the 05-10 retrain (nb17#c3; FASRC file times; section 1) [N][R]. No notebook or doc records this. Anyone comparing the four May predictions is also comparing two training datasets [I].
- **Wrong floor in the mixhvg caution**: 0.080 (M1) instead of 0.131 (CD8); 74% vs 6% (section 8) [D][R]. The F09 page found the same [D].
- **The ablation is not one-factor in the evaluation.** Each flavor is scored on its own 1,000 genes (only 674–726 shared), with its own AE, floor, ceiling and do-nothing baseline [R]. MMD, R² and every fraction therefore measure different things for the two flavors [I]. A fair test needs a common evaluation gene set.
- **It is not one-factor in selection either.** mixhvg merges species by median rank first; pearson_residuals by species count first (Setup) [C]. Two things change, while the specs say one (`conny:specs/mixhvg_m1_v08.yaml:52-57`) [D].
- **fgc_dec > 1 used as a ranking.** The hub scorecard puts the CD8 mixhvg row on top at 1.032 (ENVLOG:332-336) [D]; the value is within noise of 1 and rests on an AE that barely reconstructs held-out cells (section 7) [R][I]. Cross-AE ranking problems: [metrics.md](../metrics.md), F09.
- **One unseeded run per configuration**, no reruns: the only spread on this page is across the 10 subsampling draws, not across trainings [C][R].
- **Deployment models never validated** on held-out atlas cells; iid twins have no floor/ceiling; the `uncapped_v08` eval scripts could not have run (sections 8, 10) [R][C].
- **Normalization scale differs between training and prediction.** Training data are normalized over the 14,451 orthologs and then cut to 1,000 genes (nb15#c11, #c16; PREP) [N][R]. PNI normalizes over the 1,000 projected genes only (PNI:465-473), and so does the runbook's human-target snippet (RB:311-320) [C]. So an external cell's 1,000 genes sum to 10,000 before log1p, while the same genes of a training cell sum to only their share of its 14,451-gene total [C][I]. I found no check of this; its size was not measured. It may matter for the BCG results (F17) [I]. The 16.4 human-target cell does the same as the runbook (`conny:speciesOT/baseline/analysis/16.4_bcg_v08_predict_verify.ipynb#c10`) [C]. Two other paths made a third choice: nb16 (05-10 version) and Josh's tb3 fed scANVI-decoded `.X` to the models with no `normalize_total` or `log1p` at all (nb16#c0; `conny:tb/tb3_first_predictions.ipynb#c2`) [D]. So the same checkpoints received inputs on three different scales [I].
- **The scorer depends on an untracked repository.** EET imports `honest_metrics` from a `scgen-cellot-autoresearch/` folder inside the repo (EET:69-82) [C]. That folder is a separate repository, and this repo's `.gitignore` excludes it (`conny:.gitignore:47`) [C]. The committed `autoresearch:honest_metrics.py` is byte-identical to the FASRC copy (sha256) [R]. Yet the runbook says EET "needs no editing" (RB:648-650), and its hand-over list leaves the file out (RB:146-155) [D]. A clean clone, or the 18.7 MB hand-over plus atlas files, cannot score [I].
- **Duplicate gene ids are resolved differently.** For `--posed-ensg` input PNI keeps the first column of a repeated id (PNI:402-406). For raw input it keeps the last (PNI:439). The runbook's human snippet keeps the last and does not strip Ensembl version suffixes (RB:303, 314) [C]. This is harmless when ids are unique; otherwise the mouse and human sides could pick different columns [I]. The 2026-09-08 package plan flags the same thing (`fasrc:BK/logs/research_logs/2026-09-08-speciesot-core-populate-plan.md:512`) [D].
- **Raw-frame null passes the "trusted" metric** (model/floor 1.35, fgc_dec 0.874), and the saved run predates the warning that RB:624-625 says catches it (section 4) [R][D].
- **Unbacked numbers**: the pure-noise calibration (RB:484-501), the environment comparisons (ENVLOG:238-340) and the sidecar bit-identity (RB:588-600) have no saved files [D].
- **The v08 deployment gene axis excludes CD8 cells**: HVGs were chosen on the 88,020 non-CD8 cells (PREP), even for the no-holdout `uncapped_v08` models that reuse the file [R]. The Pearson build has no log, but the backed prep code always selects HVGs on non-holdout cells (`conny:speciesOT/hub/prep_backed.py:334-338`) [C]. Minor for prediction, but these are not "full-atlas" gene sets.
- **Confusing labels**: job names `pe_uncapped_ood_sg` for train_test models (`fasrc:BK/sbatch/train/train_hvg_pearson_residuals_uncapped_v08_scgen.sbatch`) [C]; "v07" for both a file format and a data cut; the model card lists `log1p_applied: No` for a log1p-transformed dataset (model card vs nb15#c11) [D][N].

## Terms used here

- `atlas_full` / `atlas_full_v07`: the May no-holdout deployment set (2 flavors × scGen + IMPACT) in RES/atlas_full_{flavor}; "v07" is the anndata-0.7 file suffix.
- `v08`: data built by `./hub prep` with the assay filter (mouse 10x 3' v2, human 10x 3' v3) and a species-stratified OOD split.
- `uncapped`: built from the full `tabula_*_all` files, not the ≤1,000-cells-per-type samples.
- `a`, `m1`, `m2`: holdout groups: CD8 T cells (CL:0000625); non-classical monocytes (CL:0000875); non-classical monocytes plus monocytes (CL:0000875 + CL:0000576).
- `model.pt` / `last.pt`: in a model's `cache/` folder, the best checkpoint by the test-split check / the last saved step. Prediction and evaluation use `model.pt`.
- `FASRC listing`: a directory listing made over ssh during verification (names, sizes, modification times; no file contents).
- `ood twin` / `iid twin`: the same spec with `mode: ood` (held-out half unused) or `mode: iid` (held-out half in training); both score the other half.
- `uncapped_v08_iid`, `uncapped_v08`: model-set names in PNI for RES/hvg_{flavor}_a_uncapped_v08_iid and RES/hvg_{flavor}_uncapped_v08 (train_test, 5% monitor).
- `model set`: one PNI `--model-set` choice; fixes flavors, folders and gene axis.
- `sidecar`: `genes.txt` (the model's gene order) and `scgen_shift.pt` (the two mean codes) next to a checkpoint.
- `phase 0–3`: PNI steps: axis check, gene projection, anndata-0.7 rewrite, prediction.
- `HSPC`: nb15's merged label for hematopoietic stem and progenitor cells.
- `mixhvg`: the four-method rank-max HVG ensemble; `mixhvg_default` is the three-method package default (never run here).
- `model_over_floor`: model MMD ÷ decoded floor; `conditioning`: EET's flag, "ill_conditioned" when ceiling − floor < 0.10 (EET:84-87, 486-492).
- `_selftest_*`: EET runs on M1 v08 benchmark cells, not on external data.
- `CellOT_v3`: the python 3.11 / anndata 0.10.9 env that reads both `.h5ad` formats.
