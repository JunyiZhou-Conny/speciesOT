# Experiment archaeology

This is a reference for the 83 Jupyter notebooks in the package checkout `junyizhou-conny-speciesot`. The last section explains how that package depends on scgen and cellot. It is an explanation, kept separate from the table.

The replicate column uses one rule. Yes only when the notebook is the only copy of a procedure that neither `src/speciesot` nor a hub spec already runs, and that procedure is scGen train, test, or evaluate. No for a tutorial, a one-off plot, a duplicate, or preprocessing `speciesOT/hub/prep.py:1-7` already replaced. Unknown only when the notebook has no purpose cell and the code does not say what it runs.

Result under that rule. Zero notebooks are yes. Zero are unknown. The scGen train you still have to write is not in a notebook. The committed class is `src/speciesot/speciesot_core.py:48-67`, 128 lines, with `IdentityModel` and `R2Evaluation` only. The 2026-10-14 upload `src_aa1d.zip` has the later `scGenModel` stub at `zip:src/speciesot/speciesot_core.py:212-294`. The working train is CellOT, described below.

Josh checkout `joshuaprice-speciesot` has 35 notebooks. SHA-256 of the file bytes says each one has a same-named file here. None are josh-only. Twenty-six package notebooks are byte-identical to that twin, counting same-path and moved-path twins. Nine file-byte pairs differ. For those nine, the code cells were compared too. Three of them have matching code cells and different file bytes. Six differ in code, and the twin cell says how.

`josh:notebook_descriptions.md` stops at experiment 4. The experiment 1 name in that note is e1_perturbot_interspecies1.ipynb. That filename is not on disk. The file on disk is `josh:e1_perturbot_interspecies.ipynb`. Exact filename hits in the note are only e2, e3, and e4.

A search of every `.ipynb` in this checkout for `import scgen` and `from scgen` returned no matches. When the depends column says scgen, the notebook contains the word. It does not import the Lotfollahi package.

Paths in backticks are citations. `josh:` paths are relative to the josh checkout. `zip:` paths are members of the 2026-10-14 upload and are not in git.

## Where scgen and cellot are

Three programs share the word scgen. They are not wrappers of one another.

The class being written is `src/speciesot`. `pyproject.toml:19-20` tells setuptools to look in `src`. `src/speciesot/__init__.py:1-3` exports `Experiment`. The committed `src/speciesot/speciesot_core.py:62-83` loads a yaml, builds `TrainingData` and `TestData`, and calls `model.train()` with no arguments. It never imports scgen or cellot. The only callers in the repo are `e24_src_example.ipynb` and `example_debugging.py`. Both import `Experiment`. `example_debugging.py:2` also imports `R2Evaluation`.

The upload, not git, continues that class. `zip:src/speciesot/speciesot_core.py:214-225` copies config keys onto `scGenModel`, including `x_dimension`. `zip:src/speciesot/speciesot_core.py:104` writes `x_dimensions` when `use_all_genes` is set. `zip:src/speciesot/speciesot_core.py:252-253` then reads `self.x_dimensions` into `scgen.VAEArith`. `zip:src/speciesot/Tests/config.yaml:37` spells the key `x_dimension`. `zip:src/speciesot/Tests/toy_config.yaml:19` spells it `x_dimensions`. `train` at `zip:src/speciesot/speciesot_core.py:284-285` comments out `network.train` and ends in `pass`. `predict` at `zip:src/speciesot/speciesot_core.py:287-292` mentions `_dense`, `mouse_ood`, and `human_ood`, then returns the source AnnData. This stub imports the TensorFlow package. It does not call the hub.
