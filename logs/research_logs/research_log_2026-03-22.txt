Understanding training, testing, and evaluation
- Training updates model weights, loops over training rows only
- Testing is also called validation, it is performed during training and periodically evaluate loss to choose the best checkpoint
- OOD evaluation, run model on ood mouse T and compare against ood target human T
Toy Example: train/test/ood/ignore split (CellOT toggle_ood, mode=ood)

Assume:
- 20 total cells
- condition in {mouse, human}
- holdout cell type = T
- groupby = condition
- test_size = 0.2
- random_state fixed

Step A) Initial split within each condition (80/20)
- mouse (10 cells) -> 8 train, 2 test
- human (10 cells) -> 8 train, 2 test
So before holdout overwrite:
- train = 16
- test  = 4

Step B) Holdout overwrite for T cells (toggle_ood, mode=ood)
Holdout set (all T cells):
- mouse: M3, M7
- human: H2, H9

Split holdout 50/50:
- ood    = M3, H2
- ignore = M7, H9

These labels overwrite whatever they were in Step A.

Final table:

How each split is used:
- train  : used in forward+backward pass; updates model weights
- test   : validation during training (no gradient updates)
- ood    : post-training OOD evaluation set (no gradient updates)
- ignore : discarded (not used)

Visual toy example: why "ignore" exists

Goal:
- Hold out T cells (cell_type = T)
- Compare two settings fairly:
  1) IID: model sees some T cells during training
  2) OOD: model sees zero T cells during training

Toy data (only T cells shown):
--------------------------------
Mouse T cells:  M1 M2 M3 M4
Human T cells:  H1 H2 H3 H4
Total heldout T cells = 8

Split heldout T cells 50/50 once (fixed random split, be careful with imbalance): 
------------------------------------------------------
Half A: M1 M2 H1 H2
Half B: M3 M4 H3 H4

Now apply mode:

MODE = IID
----------
Half A -> train for iid   (model is allowed to see these T cells)
Half B -> ood     (used for final OOD evaluation)

Result:
train gets: M1 M2 H1 H2
ood gets:   M3 M4 H3 H4

MODE = OOD
----------
Half A -> ignore  (throw away so model sees zero T cells)
Half B -> ood     (same OOD set as in IID mode)

Result:
ignore gets: M1 M2 H1 H2
ood gets:    M3 M4 H3 H4


Key point:
----------
The OOD evaluation set is kept IDENTICAL across modes (always Half B).
Only Half A changes role:
- IID mode: Half A helps training
- OOD mode: Half A is discarded (ignore)

That is why "ignore" exists:
it prevents leakage in OOD mode while keeping the OOD test set matched to IID mode.


If we removed "ignore" in OOD mode:
-----------------------------------
All 8 T cells -> ood
- Bigger OOD eval set (good for power)
- But no longer directly comparable to IID mode under the original protocol.
